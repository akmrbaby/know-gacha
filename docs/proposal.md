# KnowGacha ― 脳ガチャ ―

## iOSアプリ企画書 v0.2

作成日：2026年11月7日  
位置付け：初期検証に向けた企画案。アプリ名は候補。価格・最終デザイン・配信条件は未確定。

## 1. コンセプト

**一日一つ、名前しか知らなかった世界を知る。**

KnowGachaは、自然科学・技術・人文科学・社会科学・芸術などのキーワードと毎日一つ出会い、意味や背景を掘り下げ、自分の知識のつながりを育てるiOSアプリ。

「光電融合」「エスノグラフィー」「シュルレアリスム」のように、名前は耳にしても十分に説明できない言葉を入口にする。実用的な思考法や雑学だけに限定せず、その言葉を知ることで新しい分野や世界の見方が開ける体験を提供する。

ガチャは未知との出会いを楽しくする演出であり、有料抽選を必須としない。宇宙や銀河の表現も必須ではなく、知識グラフは視覚テーマから独立した機能とする。

## 2. 想定ユーザーと提供価値

主な対象は、日常的に動画・記事・対話で知識を得ており、特定の試験目的がなくても幅広く学びたい人。高校生から成人までを視野に入れるが、初期検証では好奇心の強い成人を中心にする。

| 欲求・課題 | 提供する体験 |
| --- | --- |
| 興味のある分野に情報が偏る | 自分では検索しなかった概念との出会い |
| 単語を聞いたことはあるが説明できない | 具体例・背景・誤解まで含む解説 |
| 読んだ知識がばらばらになる | 概念間の関係を確認できる知識グラフ |
| 毎日の勉強は負担になりやすい | 短い入口と、好きなだけ深掘りできる構造 |

価値の中心は、未知に出会う期待、理解する喜び、蓄積がつながる実感の三つ。滞在時間や開封回数の最大化そのものを目的にしない。

## 3. 一日の体験

1. 任意設定の通知、または自発的な起動で「今日の一語」に出会う。
2. カプセルやカードを開き、キーワードと興味を引く一文を見る。
3. 1〜2分を目安とする入口の解説で、何を指す概念かをつかむ。
4. 興味があれば、背景・具体例・論点・周辺知識をさらに読む。深掘りの所要時間は題材によって異なる。
5. 自分が過去に触れたキーワードとの関係があれば、短い説明とともに表示される。
6. お気に入り・短いメモ・関連語の閲覧を必要に応じて行う。

一日一つは「毎日の主役が一つ」という意味。関連語の短い説明や既読記事の再訪は開封待ちにしない。内容を読む前に次々と抽選する体験を中心にしない。

### 初回体験

異なる分野の五つの候補を提示し、そのうち一つを選んで最初の解説へ入る。他の候補は未読の入口として表示し、五つを学習済みにはしない。候補群には無理のない関係を含め、地図にどのような価値があるかを説明できるようにする。

### 継続の設計

初期版は一日一回の無料開封とし、石の残高管理は導入しない。開封済み教材は後日いつでも読める。欠席による連続記録の罰や教材の期間限定消失は設けない。未開封日の権利を蓄積するかは検証事項とし、MVPでは蓄積しない。通知は任意・時刻変更可能とする。

## 4. コンテンツ編集方針

### キーワードの選定

- 名前への接触機会がありながら、内容は曖昧になりやすい。
- 成立背景や具体例を知る価値がある。
- 新しい分野の入口、または世界の見方を広げる概念になる。
- 初学者向けにも、重要な区別を崩さず説明できる。
- 出典に基づく編集が可能で、単なる流行語の消費に終わらない。

候補の参考は、教養教材・現代文の概念語・歴史的な思想や芸術運動・主要な科学技術・ノーベル賞関連の概念など。既存教材の本文や独自の構成をそのまま転用せず、独自に選定・執筆する。

### 解説の構成

表現は固定テンプレートに縛らず、題材に合わせて物語・比較・図・具体例を選ぶ。一方、編集時には「何か」「背景」「具体例」「混同しやすい点」「周辺概念」「出典」が必要十分かを確認する。仕事への応用や確認問題を毎回の必須要素にしない。

1〜2分の入口だけで習得を保証しない。深掘りと、後日の関連テーマ・再訪を通じて理解を育てる。図解や短いシミュレーションは、文章より理解に役立つ題材に限って追加する。

### 品質管理

各教材に出典、内容の版、最終確認日を持たせる。事実・学説・論争・編集上の類比を区別し、更新で誤りを訂正できるようにする。生成AIを制作補助に使う場合も、出典と説明の妥当性を編集者が確認してから同梱する。

長期候補は約4,000語（毎日一語で約11年）。初期検証は約30語、次段階で100語程度、品質と継続性が確認できた後に1,000語以上を目指す。語数を増やすことより、解説と接続関係の品質を優先する。

## 5. 日々の選出ロジック

未開封の候補から、分野の偏りを抑えながら選出する。前日の内容に連続しすぎず、時々既読の概念とつながるキーワードを混ぜる。依存する前提知識がある場合は、短い補足で読めるようにする。

完全ランダムでも、個人の興味だけに最適化した推薦でもなく、編集方針を反映した偶然の出会いを目指す。重複獲得は発生させない。既知だった場合にも新しい背景を読める内容とし、「既知だった」「興味がある」の任意フィードバックを次の選出改善に使う。

初期版は端末内の単純な重み付き選出で十分。重みの具体値は試用で調整する。

## 6. 知識グラフ

### 役割

知識グラフは、収集物の一覧に加えて、概念同士の関係を理解し、過去の学びに戻るための地図。主画面から今日の解説へ直接入れるようにし、地図操作を学習の前提にしない。一覧・検索も用意する。

### ノードと進捗

「主役として開封した」「周辺で触れた」「記事を読了した」などの行動を区別して記録する。読了を理解の証明とは扱わない。お気に入りや再訪記録を持てるようにする。未学習概念も輪郭やラベルを必要に応じて表示し、説明への入口とする。

### エッジ

接続には種類、短い説明、根拠を持たせる。例は「主要な方法」「歴史的な影響」「具体例」「対立する立場」。編集者による類比は明示し、共通点だけでなく相違点も説明する。

たとえば「エスノグラフィー」と「参与観察」を、主要な調査方法という関係で結ぶ。新しい線の演出と同時に、その理由を読めるようにする。共通語があるだけで無理に結ばない。

### 配置と描画

主分野は色、複数タグは横断探索、エッジは概念間の意味に使う。2D座標は閲覧しやすさのための配置であり、距離を知識の厳密な近さとはみなさない。

初期版では事前に作成した固定座標を使い、追加更新でも既存配置を極力保つ。初期表示は自分が触れた概念とその周辺に絞る。関係は全体マスターに保持し、画面に表示するノードと進捗に合わせて線を抽出する。全ノード・全ラベルを同時に描かず、拡大率や表示範囲に応じて省略する。

## 7. UIとブランド

名称候補：**KnowGacha ― 脳ガチャ ―**  
タグライン：**一日一つ、名前しか知らなかった世界を知る。**

「ガチャ」は出会いの気軽さと意外性、「Know」は理解を表す。名称の利用可否や類似名称は公開前に確認する。

視覚テーマは未確定。カプセル、カード、標本箱、ノート、レトロな装置などを候補にし、宇宙表現を必須としない。落ち着いた読書体験と、短く気持ちのよい開封演出を両立する。

### 主要画面

| 画面 | 主要内容 |
| --- | --- |
| 今日 | 開封、未読の続き、今日のキーワード |
| 解説 | 短い入口、深掘り、関連語、出典、メモ |
| コレクション | 開封履歴、一覧検索、お気に入り |
| つながり | 知識グラフ、関係の説明、周辺探索 |
| 設定 | 通知、文字サイズ、データ書き出し・復元 |

色だけで分野や状態を伝えない。文字サイズ変更、読み上げ、演出の短縮・軽減に配慮する。レア度を知識の価値や重要度と混同させる表現は避ける。

## 8. マネタイズ

MVPでは課金を実装せず、開封後に読む意欲と継続価値を先に検証する。

将来案の第一候補は、内容が分かるテーマ別追加教材の買い切り。日々の幅広い出会いに加えて、特定分野をまとめて探索したい需要に応える。買い切りの探索機能や外観追加も候補。最終価格・無料範囲は未確定。

有料石・有料ランダム開封・期間限定知識は初期案から外す。無料の開封演出は維持する。将来、有料抽選を検討する場合には、入手確率表示、購入と消費の台帳、再インストール時の復元、返金への対応を別途設計する。

## 9. 技術構成

### 基本方針

iOSネイティブ、SwiftUIを中心とした実装を想定。教材と進捗は端末中心で扱い、自前の常時稼働バックエンドをMVPでは持たない。購入や同期を追加する場合は通信が必要になるため、すべての機能の完全オフラインをうたわない。

教材はJSON等でバンドルし、更新はアプリのアップデートで配布する。学習記録はSwiftData等、表示や通知の設定はUserDefaults等に分ける。採用API・対応OSは実装時に公式仕様で確認する。

運用サーバー費用を抑えられるが、教材編集、配信、OS対応、データ移行、問い合わせ対応の保守は残る。

### データの分離

| データ | 主な項目 |
| --- | --- |
| 概念マスター | ID、名称、主分野、複数タグ、導入文、可変の本文セクション、出典ID、内容の版、確認日 |
| 関係マスター | ID、接続元・先、関係の種類、ラベル、説明、出典ID |
| 分野マスター | ID、表示名、色 |
| 出典マスター | ID、タイトル、URL、著者・機関、参照日 |
| レイアウト | 概念ID、座標、配置の版 |
| ユーザー進捗 | 開封日時、周辺閲覧、読了日時、お気に入り、メモ、最終付与日 |

コンテンツIDは更新でも変更しない。内容の更新と進捗を分離し、教材追加で既存の記録が失われないようにする。スキーマの版と移行方針を持たせる。

### 関係データの最小例

```json
{
  "id": "ethnography_participant_observation",
  "sourceId": "ethnography",
  "targetId": "participant_observation",
  "relationType": "method",
  "label": "主要な調査方法",
  "explanation": "エスノグラフィーでは、活動への参加と観察を通じて、人々の実践や意味を理解する。",
  "sourceIds": ["ethnography_oea"]
}
```

出典レコードethnography_oeaの参照先：https://www.anthroencyclopedia.com/entry/ethnography

### 保存と復元

初期版から進捗の書き出し・読み込みを用意し、機種変更時の移行手順を明示する。自動同期は後続候補。ローカル保存だけで再インストール時の復元を保証しない。

日次開封はユーザーの現地日付を基準とし、最後の付与日を記録する。端末時計変更への厳密な対策はMVPの範囲外とする。開封記録と日次付与済み状態は一体で保存し、中断で二重開封が起きにくい処理にする。

## 11. 検証と判断基準

まず一週間、次に一か月の試用で、開封演出だけでなく本文と関係説明の価値を確かめる。

| 仮説 | 確認すること |
| --- | --- |
| 未知との出会いが魅力になる | 通知がなくても再訪するか、楽しみにしているか |
| 開封後に読む価値がある | 本文を読むか、深掘りへ進むか、途中で離れる理由 |
| 理解が残る | 数日後に、何が印象に残ったか・何を説明できるかを任意に聞く |
| 関係が理解を広げる | 接続の説明を読み、納得や発見があったか |
| 地図が役立つ | 過去の記事への再訪や探索に使われるか |
| 買いたい追加価値がある | 追加テーマの内容を示して購入意向を確認する |

MVPでは記録を端末に保持し、協力者の同意を得た書き出しや聞き取りで確認できる。サーバー分析基盤は必須としない。具体的な数値目標は初回試用を踏まえて設定し、中毒性や高い継続率を未検証のまま断定しない。

開封だけが使われる場合は解説の入口を、本文は読まれるが地図が使われない場合は地図の優先度を見直す。教材品質が維持できない場合は語数拡大を止める。

## 12. 次に決めること

1. 最初の30語と、それぞれで読者に持ち帰ってほしい理解。
2. 代表3語の完成原稿。自然科学・人文・芸術から一本ずつ試す。
3. 開封から短い解説、深掘り、関係表示までの一連の画面。
4. 知識グラフの具体的な見せ方と、必要な分類・エッジの種類。
5. 初回試用の結果に基づく学習分量、通知、無料範囲の調整。
