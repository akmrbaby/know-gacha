## #14 実機で50・100件を確認するための変更設計（2026-11-08）

ユーザーはインストール済みpreviewアプリで確認する。従来はデモが開発実行か専用フラグに限られ、preview更新が届いても入口が出なかった。expo-updatesの実際のビルドチャンネルが`preview`の場合も入口・画面を有効化し、50件を5/10/100/500件と同じデモへ追加する。productionのチャンネルは有効化しない。既存のmap-labとExpo Goの入口は維持する。

デモはGachaタブの「知識グラフのデモ」から開き、50件・100件を選択する。開封履歴・1日1回制限・保存形式を変更しない。新しいネイティブ依存・ビルド設定の変更は不要。EAS Update対応ビルドならdevelopマージ後のpreview更新で届く。未対応ビルド、更新配信失敗、異なるチャンネル／runtimeVersionの場合は受信できないため、入口がないことを実機性能の不具合とは扱わない。

受け入れ条件はpreviewで入口が出てproductionでは既定で出ないこと、50/100件で表示・タップ・ドラッグ・背景パン／ピンチ・一覧・20秒計測・終了後の履歴維持を確認できること。実機結果を得るまで#14は未完了。

### 実機での最初の確認
1. この変更を含むpreview更新の配信成功を確認し、オンラインでアプリを完全終了→起動する。ダウンロードを待ち、もう一度完全終了→起動する。
2. Gachaタブ→「検証メニュー」→「知識グラフのデモ」→「50件」。次に「100件」で同じ操作を試す。
3. 計測なしで点をドラッグ、背景をパン、ピンチ、点の詳細、一覧から個別知識への移動を確認する。
4. 各件数で「20秒間の計測を開始」し、同じ操作を繰り返す。結果JSONと端末・OS・操作感を記録する。
5. 入口がない場合は更新未反映／旧ビルド／チャンネル差を切り分ける。50件ボタンがない場合はこの変更より前の更新が動作している。

## 同じ条件を用意する

- 同じiPhone・iOS・画面の向き・リフレッシュレート設定・省電力設定で比較する。端末温度と充電状態も記録する。
- 同じコミットのExpo Goと `map-lab` のリリースビルドを使う。実行形態とEASビルドID／Expo Goバージョンを記録する。
- Gachaの「検証メニュー」→「知識グラフのデモ」を開く。取得履歴は変更しない。各試行はデモを終了して開き直し、件数を選び、5秒待って「全体」で表示を合わせる。
- 初めに計測を開始せず操作感を評価する。その後「20秒間の計測を開始」で同じ操作を繰り返す。結果は選択・コピーして下の記録へ貼る。
- 通常設定とiOSの「視差効果を減らす」を有効にした設定で繰り返す。OS設定を変更したら計測を開始し直す。

## ビルドと起動

Expo Go:

```sh
npx expo start --clear
```

実機リリース比較:

```sh
npx eas-cli@latest build --platform ios --profile map-lab
```

`map-lab` は内部配布用previewを継承し、`EXPO_PUBLIC_GRAPH_LAB=1` をビルド時に設定する。通常のproductionはこの値を設定しない。iOS識別子はユーザー指定の `com.akmrbaby.knowgacha`。Apple署名とインストール対象の端末登録が必要。ネイティブの署名済みビルド・インストール成功と、単なるJSバンドル生成成功を区別する。

## 5・10件で行う操作

1. ノードを短くタップし、そのノードの詳細が開くことを確認する。背景のタップで意図しないノードを選ばないことも確認する。
2. ノードをつかんで左右・上下・円を描くように動かす。指の下のノード、周囲の追従、解放時の飛び、解放後の収束、収束後の静止を評価する。
3. 背景をドラッグ／フリックし、ノードドラッグと区別できるか確認する。
4. ピンチで拡大縮小し、焦点位置を保つことを確認。片指→二本指→片指、ノードドラッグ中→二本指、二本指のどちらを先に離す場合も試す。意図しない選択・座標ジャンプ・固定点の残留を記録する。
5. 一覧から選択して自動カメラ移動の途中に指を置き、中断・逆方向の操作を試す。
6. 5件から「次の1件を追加」で10件まで増やす。追加前の位置とカメラが飛ばず、既存ノードの間に場所を作るか評価する。件数変更中の計測は比較不能として中断されるため、追加自体の評価は別途記録する。
7. 動きを減らす設定で、周囲の追従演出を抑えつつ直接ドラッグと探索が成立するか評価する。VoiceOverでも知識を選べることを確認する。

計測中は件数・一覧・周辺表示・画面サイズ・OS設定を変更しない。バックグラウンド移行や条件変更で `comparable: false` となった結果は、同一条件の性能比較に使わない。

## 計測値の読み方

- `frameCallbackIntervalMs`: UIランタイムのフレームコールバック間隔。p50・p95・max・サンプル数。GPU描画時間や入力遅延を測っているわけではない。
- `layout.batchesMs`: JS上の1回または複数tickをまとめた計算時間。動きを減らす設定では一括収束の時間が入るため、通常設定の1tickと同じ指標として比較しない。
- `layout.ticks`: 実行したtickの総数。停止済みなら `batchesMs: null`。0msの処理が走ったという意味ではない。
- `truncated` / `frameSamplesTruncated`: バッファ上限。上限ありの結果を完全な試行として扱わない。
- `elapsedMs`: JS側の経過時間。20秒の自動停止はJSの混雑で遅れる場合がある。

### ピンチ終了時の位置ずれ（2026-11-08、実装前）
ユーザーからiPhoneでデモの動作確認OKと、ピンチして指を離した後の位置ずれを報告された。件数別の性能合格や全操作確認を意味しない。

ピンチ終了イベントで残った1本の指へ焦点が移る場合と、2本→1本の後に背景パンの終了速度を慣性へ渡す場合を調査する。ピンチ更新は2本以上のときだけ適用し、同じ接触中にピンチがあればパン終了の慣性を抑える。1本指へ戻る際はパンの基準を取り直し、指を離した時点のカメラを保つ。次に新しく開始した1本指パンの慣性は維持する。取得履歴・保存形式・ノード物理配置は変更しない。

受け入れ条件: どちらの指を先に離してもカメラの位置・倍率が飛ばず、片指でパンを再開できること。両指同時解放とキャンセルでも位置を維持し、次の独立したパンでは通常の慣性が使えること。コールバックのイベント列を自動検証し、実際のiPhoneは更新後に再確認する。

修正・検証: 1本以下のピンチ更新を無視し、ピンチを含んだ接触の背景慣性を抑制。終了後はパンの基準を取り直す。実際のジェスチャーコールバックを取り出したイベント列テストで、左右どちらの指を残す場合・両指解放・キャンセル・片指パン再開・次の独立したパンの慣性を検証。修正前では残った指の焦点にカメラが移る失敗を確認、修正後は成功。Chromiumでも実際の2本指ズームと片方ずつの解放でカメラ位置を維持することを確認。lint・型チェック・7テストファイルが成功。iPhoneでのこの修正の再確認は未実施。
