# #7 実機評価の手順と結果

[設計・実装状態](map-interaction.md)。この記録の空欄は未検証を意味する。

## 同じ条件を用意する

- 同じiPhone・iOS・画面の向き・リフレッシュレート設定・省電力設定で比較する。端末温度と充電状態も記録する。
- 同じコミットのExpo Goと `map-lab` のリリースビルドを使う。実行形態とEASビルドID／Expo Goバージョンを記録する。
- Gachaの「知識グラフのデモ（5〜500件）」を開く。取得履歴は変更しない。各試行はデモを終了して開き直し、件数を選び、5秒待って「全体」で表示を合わせる。
- 初めに計測を開始せず操作感を評価する。その後「20秒間の計測を開始」で同じ操作を繰り返す。結果は選択・コピーして下の記録へ貼る。
- 通常設定とiOSの「視差効果を減らす」を有効にした設定で繰り返す。OS設定を変更したら計測を開始し直す。

## ビルドと起動

Expo Go:

```sh
npx expo start --clear
```

実機リリース比較:

```sh
npx eas-cli@latest build --platform ios --profile map-lab
```

`map-lab` は内部配布用previewを継承し、`EXPO_PUBLIC_GRAPH_LAB=1` をビルド時に設定する。通常のproductionはこの値を設定しない。iOS識別子はユーザー指定の `com.akmrbaby.knowgacha`。Apple署名とインストール対象の端末登録が必要。ネイティブの署名済みビルド・インストール成功と、単なるJSバンドル生成成功を区別する。

## 5・10件で行う操作

1. ノードを短くタップし、そのノードの詳細が開くことを確認する。背景のタップで意図しないノードを選ばないことも確認する。
2. ノードをつかんで左右・上下・円を描くように動かす。指の下のノード、周囲の追従、解放時の飛び、解放後の収束、収束後の静止を評価する。
3. 背景をドラッグ／フリックし、ノードドラッグと区別できるか確認する。
4. ピンチで拡大縮小し、焦点位置を保つことを確認。片指→二本指→片指、ノードドラッグ中→二本指、二本指のどちらを先に離す場合も試す。意図しない選択・座標ジャンプ・固定点の残留を記録する。
5. 一覧から選択して自動カメラ移動の途中に指を置き、中断・逆方向の操作を試す。
6. 5件から「次の1件を追加」で10件まで増やす。追加前の位置とカメラが飛ばず、既存ノードの間に場所を作るか評価する。件数変更中の計測は比較不能として中断されるため、追加自体の評価は別途記録する。
7. 動きを減らす設定で、周囲の追従演出を抑えつつ直接ドラッグと探索が成立するか評価する。VoiceOverでも知識を選べることを確認する。

計測中は件数・一覧・周辺表示・画面サイズ・OS設定を変更しない。バックグラウンド移行や条件変更で `comparable: false` となった結果は、同一条件の性能比較に使わない。

## 計測値の読み方

- `frameCallbackIntervalMs`: UIランタイムのフレームコールバック間隔。p50・p95・max・サンプル数。GPU描画時間や入力遅延を測っているわけではない。
- `layout.batchesMs`: JS上の1回または複数tickをまとめた計算時間。動きを減らす設定では一括収束の時間が入るため、通常設定の1tickと同じ指標として比較しない。
- `layout.ticks`: 実行したtickの総数。停止済みなら `batchesMs: null`。0msの処理が走ったという意味ではない。
- `truncated` / `frameSamplesTruncated`: バッファ上限。上限ありの結果を完全な試行として扱わない。
- `elapsedMs`: JS側の経過時間。20秒の自動停止はJSの混雑で遅れる場合がある。

## 技術選定と100・500件への移行（未決定）

10件でのiPhoneの感触と計測を記録した後に、d3-forceとSVGを継続するか、Skiaなどを比較するか決める。現時点ではd3-force＋SVGは試作候補。100・500件は固定配置の比較デモにとどまり、動的配置での大量表示は未達。

次段階では5・10件の回帰を残し、100・500件でラベル重なり、線の密度、縮小時のまとまり、画面外描画、全体から個別知識へたどり着けるかを実機で検証する。

## 開発環境で確認した範囲

2026-11-07、Linux Chromium 390×844、Web開発実行で手動停止・20秒の自動停止・UIフレーム集計・停止中の配置サンプルなし・件数変更時の中断・ドラッグ中の配置処理時間記録を確認。Webリリースバンドルでも専用フラグによるデモ入口と計測、`development: false` を確認。iOSのHermesリリースJSバンドルも生成成功。いずれもiPhone実機の検証結果ではない。

EASの既存iOSビルド履歴は0件。初回の非対話ビルドは `ios.bundleIdentifier` 未設定でジョブ作成前に失敗。ユーザー指定の識別子で再実行したが、内部配布用の署名情報がないため非対話モードでは設定できず、ジョブ作成前に失敗。EASはリモートのbuildNumberを1に初期化したが、署名済み成果物は作成されていない。ユーザー申告ではApple Developer Programの認証が未完了で、iPhone登録も未実施。承認後に初回のApple認証・署名設定・iPhone登録を対話端末で実施する必要がある。承認前はExpo Goで10件の操作感の評価を先行できるが、リリース比較の完了とは扱わない。
