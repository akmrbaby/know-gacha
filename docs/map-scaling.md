# #13 通常Mapと大量表示

## 方針（実装前）
2026-11-08、ユーザーの「#13を先に」の指示により、#14の10件実機評価に先行して実装する。元の順序条件は未達であり、d3-force＋SVGを暫定継続する。Skiaの採否・最終技術選定や実機性能の合格は主張しない。

目的は通常Mapと100・500件での動的配置・直接操作・探索。履歴とカメラの保存形式は変更せず、物理座標は画面内の一時状態とする。距離と線幅は意味の強さを表さない。

## 設計
- 既存の独立した配置エンジンを全規模で有効化。追加は現在位置を保持し、隣接点の近くへ種を置く。
- 初期化の近傍検索を隣接表へ変更。通常は1フレーム1tick。動きを減らす場合も時間予算付きで収束を分割し、長い同期ループを避ける。
- 線を通常・接続・選択の3本のSVGパスへまとめ、画面外の線を除外。ラベルは既存の画面座標・優先順位・重なり回避を維持する。
- 画面外のノード・関係ラベルはマウントしない。縮小時は画面のセルごとに代表点と件数を表示し、選択点と接続点を優先。まとまりは画面上の近接であり意味分類ではない。全体→代表点選択／拡大→個別知識、または一覧で探索する。
- 描画対象の更新は120ms間隔、対象が変わったときだけReactを更新。位置とジェスチャーは既存shared valueで追従する。

## 受け入れ・検証計画
通常Map・5/10/100/500件、追加時の位置維持、ドラッグ後の収束・停止、画面外と線の交差判定、縮小時の件数保持を自動検証する。lint・型チェックとWebの探索／パン／表示を確認する。iPhoneの複数指操作、VoiceOver、Expo Go／リリース性能は#14に実測を残す。Webの結果を実機確認としない。

## 実装・検証結果
- 通常Map・全件数デモへ適用。初回は既存座標を初期値に使い、カメラとの整合を保つ。固定位置のままにはせず、以降は力学計算で更新する。
- 近傍の全エッジ走査とノードごとの重心再計算を隣接表・1回の重心計算へ変更。縮小表示は未選択ラベルと通常線を隠す。個別表示では従来の文字サイズ・優先順位を使う。
- 線の出現アニメーションを個別パスから一括描画へ変更したため、従来の線ごとの遅延アニメーションは廃止。ノード出現は維持する。
- lint・型チェック、5テストファイルが成功。500ノードの有限座標・追加直後の既存位置保持・固定／解放・収束停止と、代表点の件数保持／優先点／画面外判定を検証。

- 500件の全体から点の中心タップで詳細を開き、フォーカス後に画面外ノードが除外されることを確認。

## 制約と未検証
