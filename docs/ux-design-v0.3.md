# KnowGacha UX設計 v0.3 — Gachaと全画面Map

- 状態：設計中・未実装。
- 作成日：2026-11-07
- 前版：[v0.2](ux-design-v0.2.md)。実機で機能は確認されたが、「Webアプリを貼ったように感じる」というフィードバックを受け、構造と操作感を見直す。
- ユーザーから確認できた方向：タブはGachaとMap。Gachaで残り回数分を開封し、文章で知識を学ぶ。Mapでその全体像を見渡す。Mapは画面全体を使う。

## 1. 画面の役割

| タブ | 役割 | 主な操作 |
| --- | --- | --- |
| Gacha | 新しい知識と出会い、文章で学ぶ | 残り回数を確認 → 回す → 結果 → 読む |
| Map | 出会った知識の全体像と関係を探索する | 地図を動かす → 語を選ぶ → 関係を確かめる → 読み返す |

タブ名は `Gacha` と `Map`。読書は両タブから開ける共通の詳細画面とし、独立した3つ目のタブにはしない。日本語の説明を添え、初見でも役割が分かるようにする。

## 2. Gacha

上部にアプリ名と「残り○回」、中央に触りたくなる抽選物、指が届きやすい位置に「ガチャを回す」を置く。カード状の説明や操作ボタンを縦に積み重ねたホームを改め、開封操作を画面の主役にする。

開封後は語名と導入文を表示し、「読む」から文章主体の解説へ進む。短い入口と深掘りの構成は維持する。結果から勝手に読書画面やMapへ飛ばさず、ユーザーが進むタイミングを選べるようにする。

残り回数があれば読書から戻って再び回せる。残り0回ではボタンを消すだけでなく、回復条件の説明と、既に出会った知識を読む入口を表示する。付与ルールが確定するまでは「明日回復する」などの表示は確定しない。

結果には「Mapで見る」を副操作として用意し、対象の語へカメラが寄ったMapを開く。開封済み教材の再閲覧は回数を消費しない。未開封教材がなくなった場合は、残り回数があっても重複抽選や回数消費を行わない。

### 回数制と保存の境界

**付与数・回復タイミング・蓄積上限・初回ボーナスは未確定。** ユーザーに確認中。残り回数を表示することと、回数の付与ルールを分離して設計する。課金や購入通貨は今回導入しない。

現行実装は日付ごとに一語へ固定している。複数回の開封を許す場合は仕様変更になるため、付与ルールの確定後に進捗スキーマの移行を設計する。旧v1の履歴・今日の語を保持し、追加の権利を誤って二重付与しない。回数消費と開封記録は一体で保存し、保存成功後に結果演出へ進む。

## 3. Map — 地図そのものを画面にする

Mapタブのコンテンツ領域全体を地図にする。ページの中に高さ260pxの地図を埋め込む構成は廃止する。下部タブとセーフエリアを考慮しつつ、地図は背面に広がる。地図全体を外側の縦スクロールに入れない。

```text
┌──────────────────────────────┐
│ Map · 出会った知識     [一覧] │ ← 小さな操作を重ねる
│                              │
│      ○ ───── ◉               │
│       ╲       ╲              │
│        ○       ○             │
│                              │
│   ○ ─── ○                    │ ← 地図を直接操作
│                              │
│                       [全体] │
│                              │
│ 〈選択した時だけ詳細シート〉  │
├──────────────────────────────┤
│        Gacha     Map         │
└──────────────────────────────┘
```

枠線付きの地図コンテナ、常設の大きな説明パネル、複数行の操作説明は置かない。説明は初回の短いヒントと、選択時の詳細へ移す。

### 指への応答

- 1本指のドラッグに即座に追従し、離すと自然に減速する。
- ピンチは2本指の中心を基準に拡縮し、見ている対象が不意に逃げない。
- パンとピンチを連続・同時に扱い、指の本数が変わっても位置が跳ばない。
- ノード選択時は対象が詳細シートに隠れない位置へ滑らかに寄る。
- 「全体」で表示中の知識の範囲へ滑らかに戻る。無限に遠くへ移動して迷った場合も復帰できる。
- 通常操作を＋／−ボタンに依存させない。読み上げ向けには拡大・縮小・選択の代替操作を残す。

Reactの状態更新だけで毎フレームのカメラ位置を描き直す現行方式は見直す。描画・ジェスチャー・アニメーションの採用技術はSDK互換性と実機試作で確認し、確定結果を追記する。React Nativeの継続を前提とし、Swiftへの移行は現時点では行わない。

### 表示する情報量

遠くから見ると分野のまとまりと主要な語が分かり、寄ると周辺語や関係のラベルが読める。すべての文字を常に同じ密度で表示しない。切り替えには余裕を持たせ、拡縮の境界でラベルが点滅しないようにする。

初期範囲は「開封済み教材と、その周辺」の全体像。未開封教材をすべて公開するかは別の判断とし、今回の全体表示には含めない。周辺語と開封済み教材の状態は区別する。開封数を習熟度として扱わない。

固定配置でも、カメラ操作・選択・出現の動きは滑らかにする。常時揺れる物理演算を楽しさの前提にしない。意味のない関係線は作らず、距離が意味の厳密な近さではないことは補助説明に残す。

### 選択時の詳細シート

未選択時は地図を広く見せる。ノードや線を選ぶと、画面下から詳細シートが現れる。

最初は語名と短い説明、教材なら「読む」、関係なら両端の語と関係の理由を表示する。引き上げると詳しく読め、引き下げるか背景タップで閉じられる。シート操作中に背面の地図が誤って動かないようにする。

解説から戻ったときは、地図の選択・カメラ位置を維持する。Mapタブを往復しただけで毎回全体へ戻さない。Gachaの結果から「Mapで見る」を選んだ場合は、その語へ明示的にフォーカスする。

### 追加されたことの表現

新しい知識を得た後にMapを開くと、新しいノードが現れ、関係線が順に伸びる。演出終了を操作の前提にはしない。すでに見た追加演出をタブ往復ごとに再生しない。動きを減らす設定では最終状態をそのまま表示する。

Mapが空なら、地図の背景に短い案内とGachaへの入口を置く。一覧は補助操作として開き、同じ語と関係へ読み上げでも到達可能にする。

## 4. 次の実装単位

1. **Mapの操作感を先に検証**：少量の試作データで全画面、パン・ピンチ・慣性・カメラ移動・詳細シートを作る。iPhoneで操作して評価する。
2. **情報の見せ方を整える**：拡縮に応じたラベル、選択強調、新しいノードと線の出現、一覧との対応。
3. **Gachaの画面構成を整える**：残り回数と開封を主役にし、結果・読書・Mapをつなぐ。
4. **付与ルール確定後に保存を拡張**：残り回数、付与記録、複数回の開封と既存進捗の移行を実装・検証する。

付与ルールが未確定でも、Mapの設計と試作は進められる。新しい回数消費の仕様は、確定するまで実装しない。

## 5. 受け入れ条件

- タブはGachaとMapの2つで、目的が見て分かる。
- Mapは画面の主役であり、外側のスクロールや常設説明パネルと操作が競合しない。
- iPhoneでドラッグ・ピンチ・指を離す・選択の一連の操作が途切れず、中心位置が不意に跳ばない。
- 詳細シートを閉じると、すぐ地図の探索に戻れる。
- 一覧と読み上げでも、教材・周辺語・関係の説明へ到達できる。
- Gachaは残り回数と利用できない理由が分かり、抽選と読書・再閲覧の操作を混同しない。
- 未開封教材の枯渇、連打、保存失敗、再起動で権利や開封記録が壊れない。
- 画面設計は実機で評価する。ブラウザのスクリーンショットや型チェックだけで操作感を確認済みにしない。
