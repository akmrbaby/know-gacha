# Map操作と動的配置 — #7

## 目的・範囲
固定配置から、関係による引力・反発・衝突回避のある探索へ進む。最初は5・10件のみを試作対象とし、10件のiPhone評価と技術選定を記録してから100・500件へ拡張する。#6の大規模固定座標デモは比較材料として残す。

## 計画する画面と操作
Map背景はパン／ピンチ、ノードは直接ドラッグ。タップと移動を区別し、複数指へ切り替わった際はノードを解放する。指を置いた時点で自動カメラ移動を中断する。ドラッグ中に周囲が追従し、解放後に収束して停止する。追加時は既存位置を引き継ぐ。近接は意味的類似度や関係の強さを保証しないことを画面に示す。

## 責務・技術候補
配置エンジンは座標・速度・固定点・冷却を持ち、カメラやReactを知らない。描画は座標を購読し、ジェスチャーは固定点を更新する。フレームごとのReact state更新を避ける。d3-forceとSkiaは候補であり、最終採否は10件のiPhone評価後に決める。

- [d3-force公式](https://d3js.org/d3-force/simulation): 手動tick、冷却、固定点、再加熱が可能。入力ノードを変更するため、知識モデルから分離したコピーが必要。
- [SDK 58 Skia](https://docs.expo.dev/versions/v58.0.0/sdk/skia/): Expo Goに同梱。WebはCanvasKitの準備が別途必要。現行SVGとの実機比較は未実施。

## データ・永続化
知識・関係・取得履歴は変更しない。配置は画面内の一時状態。追加時の位置維持はそのセッション内で行い、永続化は今回導入しない。

## 実機比較用の計測・配布（実装済み・実機未検証）
専用 `map-lab` ビルドでのみ、開発実行以外でもデモの入口を表示する。通常のproductionビルドでは有効にしない。Expo Goと同じ5・10件の手順をリリースビルドでも試せるようにする。

計測は利用者が開始し、停止または20秒で結果を表示する。UIランタイムのフレームコールバック間隔とJS側の配置tick／一括収束の処理時間を別々に集計し、件数・表示方式・OS・実行形態・動きを減らす設定・表示領域をJSONに含める。UIフレーム間隔はGPUの描画時間や入力遅延そのものではない。収束後に配置処理が発生しなかった場合は0msとせずサンプルなしと記録する。計測自体にも負荷があるため開始前の操作感も別途評価する。

件数・周辺表示・OS設定・表示領域の変更やバックグラウンド移行時は比較不能として中断理由を記録する。結果は端末内の一時表示のみで、自動送信も取得履歴への保存も行わない。端末の機種、端末温度、リフレッシュレート設定、ビルドID／コミット、操作手順と感触は別途検証記録へ追記する。

## 受け入れ条件・検証順
1. 配置エンジンで関係による配置変化、固定点、周辺追従、収束停止、追加時の既存位置維持を自動検証。
2. 5・10件でタップ、背景パン、ノードドラッグ、ピンチ、片指復帰、自動移動中断、動きを減らす設定をiPhoneで確認。
3. 同一端末・OSのExpo Goとリリースビルドでフレーム時間・配置tick時間・操作感を比較。端末、OS、実行形態、件数、p50/p95/max、ジャンプ・誤選択の有無を記録。
4. 10件の評価後に配置・描画方式を決め、100・500件の密度、まとまり、画面外描画、個別知識への到達を調整・計測する。

## 現在の状態
配置エンジンの独立ラッパーを実装済み。d3-forceの手動tickを使い、自動タイマーを起動しない。関係による引力、反発、衝突回避、固定点、解放後の冷却・停止、追加時の既存座標維持を持つ。自動テストで関係の有無による配置差、固定点と周辺追従、収束停止、追加・削除、元データの非変更を確認済み。

### 10件試作の画面統合（実装済み・実機未検証）
`graph-demo` の5〜10件に限って動的配置を有効化。本番Mapと100・500件の比較デモは固定配置を維持する。これは10件の実機評価を先に行うための段階導入であり、#7の最終状態ではない。

- `useGraphLayout` が手動tickを必要な間だけrequestAnimationFrameで実行し、座標をshared valueへ公開。全ノードのReact再レンダーを毎フレーム起こさない。d3自体はJSランタイム専用で、UI workletから呼ばない。
- つかんだノードの座標はUIランタイムで上書きし、JSが遅れても指への直接追従を維持する。JS側は固定点をフレームごとに読み、周囲を更新する。ジェスチャーからJSへの通知は開始・解放時のみ。
- タップ判定・線・ラベル・カメラは更新後の同じ座標を参照する。線は判定と見た目を一致させるため直線へ変更。背景の淡いノード別の円は描画要素削減のため除去した。
- ノード移動と背景パンを区別し、複数指への切り替え・キャンセルで固定点を解放する。最後のドラッグ位置をエンジンが受け取るまで表示を保つ。移動した操作からのタップ選択を抑止する。
- 追加時にCanvasを再マウントせず、カメラも移動しない。新ノードは残っている隣接ノードの近くへ追加。初期配置は検証用格子に依存せず、中心付近の決定的な螺旋を種にする。
- 動きを減らす場合は配置をまとめて計算し、追従する周囲のアニメーションを抑制。つかんだノードは直接動き、解放時に周囲を即時再配置する。
