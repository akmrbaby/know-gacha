# Map操作と動的配置 — #7

## 目的・範囲
固定配置から、関係による引力・反発・衝突回避のある探索へ進む。最初は5・10件のみを試作対象とし、10件のiPhone評価と技術選定を記録してから100・500件へ拡張する。#6の大規模固定座標デモは比較材料として残す。

## 計画する画面と操作
Map背景はパン／ピンチ、ノードは直接ドラッグ。タップと移動を区別し、複数指へ切り替わった際はノードを解放する。指を置いた時点で自動カメラ移動を中断する。ドラッグ中に周囲が追従し、解放後に収束して停止する。追加時は既存位置を引き継ぐ。近接は意味的類似度や関係の強さを保証しないことを画面に示す。

## 責務・技術候補
配置エンジンは座標・速度・固定点・冷却を持ち、カメラやReactを知らない。描画は座標を購読し、ジェスチャーは固定点を更新する。フレームごとのReact state更新を避ける。d3-forceとSkiaは候補であり、最終採否は10件のiPhone評価後に決める。

- [d3-force公式](https://d3js.org/d3-force/simulation): 手動tick、冷却、固定点、再加熱が可能。入力ノードを変更するため、知識モデルから分離したコピーが必要。
- [SDK 58 Skia](https://docs.expo.dev/versions/v58.0.0/sdk/skia/): Expo Goに同梱。WebはCanvasKitの準備が別途必要。現行SVGとの実機比較は未実施。

## データ・永続化
知識・関係・取得履歴は変更しない。配置は画面内の一時状態。追加時の位置維持はそのセッション内で行い、永続化は今回導入しない。

## エッジの視認性改善（実装済み・Web確認済み、実機未検証）
10件試作へのフィードバックを受け、接続をたどれる線の表示に調整する。Mapとデモの共有描画に適用する。カメラ縮小で線幅まで細くなっていたため、線幅を縮尺で補正し、画面上の太さを維持する。通常は背景より濃い線、縮小時は控えめな濃さとし、選択ノードに接続する線と直接選択した線を色・太さで強調する。選択と無関係な線は薄く残して周囲の文脈を保つ。新しいアニメーションは加えず、動きを減らす設定でも同じ表示にする。

知識・関係のモデルと保存データは変更しない。線の太さ・濃さは選択状態を示し、関係の強さを表さない。受け入れ条件は、5・10件の全体表示で線が見えること、拡大縮小で極端に細く／太くならないこと、ノード選択で接続線だけを強調できること、選択解除で元に戻ること。100・500件は既存の固定配置比較デモで表示の回帰を確認し、動的配置の拡張とは扱わない。Webで描画と操作を確認し、実機の視認性は別途確認する。

実装: 通常の線幅を画面上1〜1.6px、接続線の強調を2.2px、直接選択した線を2.8pxとし、worldの縮尺を補正。通常色は濃い緑灰色、強調時は接続元ノード色。非選択線の濃さは縮尺に応じて変え、選択中の無関係な線は薄く残す。

検証: 2026-11-07、Linux Chromium 390×844・動きを減らす設定のWeb開発実行で、10件の全体表示、光電融合への接続3本のみの強調、線自体の選択、選択解除、全体／フォーカス時の画面上の線幅を確認。5・100・500件の固定配置比較デモでも有限の線幅と描画エラーなしを確認した。100・500件の操作性・密度が解決済みという意味ではない。スクリーンショットは `/tmp/map-edges-overview.png` と `/tmp/map-edges-selected.png`。lint・型チェックは通過。iPhone実機の視認性は未確認。

## 実機比較用の計測・配布（実装済み・実機未検証）
専用 `map-lab` ビルドでのみ、開発実行以外でもデモの入口を表示する。通常のproductionビルドでは有効にしない。Expo Goと同じ5・10件の手順をリリースビルドでも試せるようにする。

### iPhoneでエッジが表示されない報告への対応（画面内描画へ変更・実機再確認待ち）
線幅の調整後も、ユーザーのiPhoneでは5〜10件デモのエッジが見えないとの報告。前回のWeb確認はiPhoneでの解消を証明しない。EAS Simulatorの利用可否は `available: false` で、自動のiOS再現環境は用意できていない。

実際の描画領域を検査すると、390×404の表示領域に対してエッジ用SVGが12,000×12,000だった。これはネイティブ描画面の過大化につながるため、最初の切り分けとして画面サイズのSVGへ変更する。線の座標をUIランタイムでカメラ座標へ変換し、ノードと同じ座標系で描画する。巨大なSVGを丸ごと変形する方式をやめ、線幅は画面座標のまま扱う。保存・知識モデル・ジェスチャーは変更しない。

受け入れ条件: SVGの領域が画面サイズ内に収まること、線とノードの端点がパン・ズーム・ノード移動中も一致すること、既存の線の強調が維持されること。Webでこれらを確認したうえで、画面の「線表示 v2」を目印にiPhoneで再確認する。ネイティブで見えない原因と解消は、この再確認まで未確定。

確認結果: Webの実際の描画を検査する `/tmp/knowgacha-browser/map-edge-surface-check.cjs` は、変更前に `width: 12000, height: 12000` で失敗、変更後に `width: 390, height: 381`（表示領域も390×381）で成功した。ノードをつかんでいる間・解放後・背景パン・カメラフォーカス後も、線の端点とノード中心が1画面単位以内で一致することをWebで確認。iOSのHermes JSバンドルも生成成功。これらはネイティブの表示解消を証明するテストではなく、iPhoneの再確認結果は未取得。

任意のWeb回帰チェックを `tests/browser/map-edges.cjs` に記録した。Expo Webを起動したうえでPlaywrightを利用できる環境から実行する。標準のユニットテスト／CIにはPlaywrightのインストールを追加していない。

```sh
node tests/browser/map-edges.cjs
# 別の場所のPlaywrightを使う場合はMAP_PLAYWRIGHT_MODULEにモジュールのパスを指定
# 別の開発サーバーはMAP_TEST_URLで指定（デフォルト http://127.0.0.1:8082）
```

初版の「線幅が縮小されることが主因」という説明はiPhoneの原因確定としては不十分だった。初版はworldサイズSVGの線幅を補正し、v2は表示領域サイズのSVGへ画面座標で線を描く。太さ・色による選択表現は維持する。

計測は利用者が開始し、停止または20秒で結果を表示する。UIランタイムのフレームコールバック間隔とJS側の配置tick／一括収束の処理時間を別々に集計し、件数・表示方式・OS・実行形態・動きを減らす設定・表示領域をJSONに含める。UIフレーム間隔はGPUの描画時間や入力遅延そのものではない。収束後に配置処理が発生しなかった場合は0msとせずサンプルなしと記録する。計測自体にも負荷があるため開始前の操作感も別途評価する。

件数・周辺表示・OS設定・表示領域の変更やバックグラウンド移行時は比較不能として中断理由を記録する。結果は端末内の一時表示のみで、自動送信も取得履歴への保存も行わない。端末の機種、端末温度、リフレッシュレート設定、ビルドID／コミット、操作手順と感触は別途検証記録へ追記する。

## 現在の状態
配置エンジンの独立ラッパーを実装済み。d3-forceの手動tickを使い、自動タイマーを起動しない。関係による引力、反発、衝突回避、固定点、解放後の冷却・停止、追加時の既存座標維持を持つ。自動テストで関係の有無による配置差、固定点と周辺追従、収束停止、追加・削除、元データの非変更を確認済み。

### 10件試作の画面統合（実装済み・実機未検証）
`graph-demo` の5〜10件に限って動的配置を有効化。本番Mapと100・500件の比較デモは固定配置を維持する。これは10件の実機評価を先に行うための段階導入であり、#7の最終状態ではない。

- `useGraphLayout` が手動tickを必要な間だけrequestAnimationFrameで実行し、座標をshared valueへ公開。全ノードのReact再レンダーを毎フレーム起こさない。d3自体はJSランタイム専用で、UI workletから呼ばない。
- つかんだノードの座標はUIランタイムで上書きし、JSが遅れても指への直接追従を維持する。JS側は固定点をフレームごとに読み、周囲を更新する。ジェスチャーからJSへの通知は開始・解放時のみ。
- タップ判定・線・ラベル・カメラは更新後の同じ座標を参照する。線は判定と見た目を一致させるため直線へ変更。指を置いた時点で進行中のカメラ移動を止め、JS側で待機していた移動要求もUI側で接触中なら開始しない。背景の淡いノード別の円は描画要素削減のため除去した。
- ノード移動と背景パンを区別し、複数指への切り替え・キャンセルで固定点を解放する。最後のドラッグ位置をエンジンが受け取るまで表示を保つ。移動した操作からのタップ選択を抑止する。
- 追加時にCanvasを再マウントせず、カメラも移動しない。新ノードは残っている隣接ノードの近くへ追加。初期配置は検証用格子に依存せず、中心付近の決定的な螺旋を種にする。
- 動きを減らす場合は配置をまとめて計算し、追従する周囲のアニメーションを抑制。つかんだノードは直接動き、解放時に周囲を即時再配置する。

### 検証記録
2026-11-07: Linux上のChromium、390×844 CSS px、Web開発実行で、ノードの横55px・縦30pxのドラッグに同量追従、ドラッグ後に選択しないこと、5→10件の追加、ランタイムエラーなしを確認。10件の画面を `/tmp/map-interaction-10-web.png` に保存して確認。追加のWeb回帰で、自動カメラ移動中に指を置いて位置が変わらなくなることを確認。同じWeb環境で通常設定と `prefers-reduced-motion: reduce` の両方について、収束後に座標が変化しないこととタップで詳細が開くことも確認。これはiPhoneの操作感・ネイティブ描画負荷の検証ではない。

制約: 配置の冷却はtick数で進むため、低フレーム時は収束までの実時間も長くなる。Web回帰では4秒の固定待機では収束途中のケースがあったため、上限付きで座標の完全停止を観測して確認した。実機でも収束までの待ち時間を評価する。
