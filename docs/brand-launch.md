# アイコンと起動演出（2026-11-09、実装前）

共通モチーフは「カプセルから知識がつながる」。深いティールの背景、アイボリー／淡いミントのカプセル、3つの点とコーラルの先端で表す。画像生成したアイコンをアプリ用に書き出し、起動画面とアプリ内では同じモチーフのベクターを使用する。文字を入れず、小さいホーム画面表示でも形が分かるようにする。

OSの静止起動画面からアプリ内のマークへつなぎ、点が順に現れる約520msの演出で画面を表示。データ読み込みと並行し、読み込み済みなら演出後に通常画面へ。読み込み失敗は再試行画面を隠さず表示し、演出に依存して永久に待たないよう最大1800msで解除する。動きを減らす設定では静止表示、バックグラウンドへ移った場合は演出を終了。コールド起動ごとに1度、タブ移動や前景復帰では再生しない。Gachaの開封演出・取得権利・保存データには影響しない。

SDK 58公式のexpo-splash-screenを追加し、アプリversionを1.0.1へ更新して既存1.0.0のruntimeVersionと分離する。iOS/AndroidのアイコンとOS起動画面は新しいEASビルドが必要。既存1.0.0へ互換性のないJSを配信しない。Androidのadaptive foregroundは透明背景で安全域を確保、単色アイコンも用意する。Web faviconも統一する。

## 検証計画
画像サイズ・不透明度・adaptiveの安全域、設定プラグインとruntimeVersion、lint・型チェック、Webの初回起動／通常復帰／動きを減らす／読込み失敗、iOS exportを確認する。実機のOSスプラッシュとインストールアイコン・ネイティブ背景復帰の見え方は新ビルドで確認する。

## 実装と確認
- 不透明な1024pxアプリアイコン、64px favicon、透明の1024px起動画面マーク、Android adaptive foregroundと単色版を用意。元の画像生成結果はworkspaceのgenerated_imagesに保持し、配布用サイズへ書き出した。起動用とadaptive用は同じ形をベクターで整えて使用し、SVG原稿もassets/brandへ保存。
- OSの起動画面はカプセル部分だけを表示し、JSの最初のフレームとつなぐ。400msで点を順に表示、準備ができれば120msで消える。データが遅ければマークを保持し、最大1800msで通常の読み込み／再試行UIへ渡す。動きを減らす場合はアニメーションしない。アプリが背面へ移る場合も終了する。
- lint・型チェックと既存7テストファイルが成功。Webの通常起動は約584ms、動きを減らす設定は約192ms（この環境の測定）。タブ移動時の再生なし、壊れた保存の読込み失敗と再試行を確認。これはiPhoneの起動時間ではない。
- iOS Hermesバンドル生成とExpoネイティブ設定のintrospect成功。ネイティブiOSのversionが1.0.1、runtimeVersionはappVersionで分離。アイコンの寸法と不透明度、Androidの不透明ピクセルが66dpの円形安全域に収まることを確認（1024px画像の最大半径295.9px、上限312.9px）。
- 実機のOS起動画面・ホーム画面アイコン・前景復帰の見え方は新ビルドで未確認。Expo Go／Webでの表示はネイティブ起動画面の代わりにはならない。

## 実機で確認する手順
マージ後、ActionsのiOS Previewで1.0.1の新ビルドを作成し、同じbundleIdentifierのアプリへ上書きインストールする。アプリの削除は不要。旧1.0.0へのOTA更新だけではアイコン・新しいスプラッシュモジュールは変わらない。ホーム画面アイコン、コールド起動、動きを減らす設定、バックグラウンド復帰、既存の取得履歴の保持を確認する。
