# アイコンに残り開封回数を表示する（2026-11-11）

状態: 実装・自動テスト・Web設定表示・iOS export済み。実際のアイコン表示と日付切替は実機確認待ち。

## 目的・表示

iPhoneのホーム画面にあるアプリアイコンのバッジで、あと何回開封できるかを知らせる。当日分と初回特典の合計を未取得教材数で制限し、0回なら非表示。未読記事数や通知の未読数とは区別する。

設定に「アイコンに残り回数を表示」を追加。初期はオフ、利用者がオンにするとOSの通知許可を求める。リマインダーとは別にオン/オフ可能。通知の許可を得ても毎日のリマインダーは自動でオンにしない。日本語と英語、読み込み失敗・保存失敗・再試行・端末設定への案内を用意する。

## 同期・翌日

保存済みの進捗を使い、起動・開封成功・日付変更・前面復帰で現在の数を同期する。進捗の読込みに失敗した場合、仮の初期10回を反映しない。明示的なオフと許可取消しは進捗読込み失敗時でも予約を取り消し、バッジを消す。

iOSでは、本文・タイトル・音を持たないバッジのみの通知を毎日0時に予約する。翌日の数は `min(未取得教材数, 未消費特典数+1)` で固定し、日をまたいでも当日分を積み上げない。開封ごとにこの予約を見直す。全教材取得済みなら予約を取り消す。1件の繰り返し予約なので、既存のリマインダー最大60件と合わせてもiOSの予約上限64件以内。

OSによる実際の反映時刻は保証しない。移動・タイムゾーン変更後は前面復帰時に現地の状態へ同期。アプリが前面にいる場合の通知ハンドラーではバッジを直接書き換えず、進捗と日付を使う通常同期に任せる。これにより、開封と予約配送の競合で古い回数を戻さない。

## 互換性・範囲

設定は独立した保存キーで管理。進捗・初期特典数・通知・言語・Mapの保存データを変更しない。予約は専用IDだけを管理し、既存リマインダーの予約・解除と互いに干渉しない。通知許可の要求ではbadgeを含める。OSでバッジだけ無効なら端末設定へ案内する。

今回はiOSを対象とする。Androidはランチャーによって数値バッジの対応が異なるため、同等の表示を約束しない。Webは非対応として案内する。既存expo-notificationsを使い、新しいネイティブ依存やruntimeVersion変更は不要。

## 検証条件

- 初期10回→開封9回、日次分を消費後の翌日分、特典0で0→翌日1、未取得数による上限、全件取得済みの0。
- 数日閉じても当日分は1だけ。旧教材取得と保存済み特典数を維持する。
- 明示的な許可要求、OSのバッジ拒否・取消し、オフ、保存失敗、予約失敗後の再試行、連続更新の最終状態を検証。
- 本文・音のない予約は専用ID1件。リマインダーのオン/オフで消えず、逆にその予約にも干渉しない。
- lint・型チェック・回帰テスト・iOS export、設定画面の日英Web表示を確認。ホーム画面での表示、バックグラウンドでの0時更新、OS設定の影響は実機で別途確認する。

参考: [Expo SDK 58 Notifications](https://docs.expo.dev/versions/v58.0.0/sdk/notifications/) のsetBadgeCountAsync・NotificationPermissionsStatus・CalendarTriggerInput。

## 実装・検証記録

- 独立キー`knowgacha.badge.v1`にオン/オフのみ保存。専用ID`knowgacha.badge-rollover.v1`の繰り返しカレンダー予約を1件管理する。新たなネイティブ設定・依存・バージョン変更はない。
- 通知許可の要求に`allowBadge: true`を追加。許可の読み取りだけではOSダイアログを出さない。iOSの`allowsBadge`も確認し、通知の許可だけがあってバッジが無効な場合は端末設定へ案内する。バッジのオン操作でも標準の通知許可を使うが、リマインダーの保存済みオン/オフは変えない。
- 保存失敗では設定や進捗を上書きしない。予約更新失敗は再試行可能。進捗が読めなくても明示オフ・OS許可取消しの際は予約とバッジを解除する。
- 単体テストで初期10、開封後9、特典0で当日0/翌日1、未来の日付でも1だけ、将来の初期3、教材数による上限・旧教材・全件取得を確認した。予約はタイトル/本文なし、音false、0時の繰り返し1件で、同じ数の再同期は予約を増やさない。
- iOSアダプターのモックで、バッジ個別の許可、明示的な許可要求、更新失敗、リマインダー予約を残す取消しを確認。逆にリマインダーのオフでもバッジ予約が残ることを確認した。
- 既存の初期10回、保存失敗・連打、途中再起動、日英の検索・記事/Map往復、翌日の付与、全30件取得済みのWeb回帰試験が成功。
- 日英/320×568/暗色の設定画面で、Webは非対応の説明だけを表示し、動かないスイッチを出さないこと、進捗を消費しないことを確認した。
- lint・型チェック・iOS Hermes export成功。ブラウザではホーム画面のバッジ自体は検証できない。新しいiOSビルドは必須ではなく、1.0.4向けの互換更新として配信可能。マージ・配信は未実施。

5. リマインダーをオフにしてもバッジが残り、バッジだけオフにすると消えることを確認。OSのバッジ無効/有効を切り替えて復帰時に追従することを確認する。
6. 背景・再起動・タイムゾーン変更・全件開封済みを確認。端末/OS/実行形態と配送時刻を記録する。
