# 毎日のガチャのリマインダー（2026-11-10）

## 実装前の設計

一日一回、知らなかった分野の言葉に出会う習慣を支える。端末内で予約するローカル通知を追加し、サーバーやPushトークンは使わない。通知は任意・時刻変更可能という企画書の方針を採用する。

### 画面と操作

- Map／Gacha右上の設定に「毎日のリマインダー」を追加する。初期はオフ、時刻の初期値は20:00。オンにした操作でだけOSの通知許可を求め、起動時には許可ダイアログを出さない。
- オン・オフ、端末の時刻に合わせた時刻選択、5秒後のテスト通知を用意する。許可を拒否した場合は端末の設定を開く導線を示す。設定の読込・保存・予約に失敗した場合はエラーと再試行を表示する。
- 当日の無料ガチャを開封済みならその日の通知を取り消す。抽選対象をすべて取得した場合も予約を止める。通知を押すとGachaタブを開き、勝手に抽選しない。通常通知はアプリを見ている間は表示しない。テスト通知は前面でも表示する。
- 文面はアプリで選んだ日本語・英語に合わせる。時刻・言語・日付・進捗・端末の通知権限が変わったら予約を照合する。OSの通知許可、集中モード、省電力設定に従う。
- Webでは通知が端末アプリ用であることを表示し、ブラウザの許可を要求しない。

### 予約とデータ

- 新しい保存キー `knowgacha.reminders.v1` にオン・オフと時・分を保存する。履歴・権利・言語・Mapカメラのキーや形式は変更しない。読めない設定を無断で初期化しない。
- 毎日繰り返す通知では当日の開封済み判定を背景で行えないため、次の60日分を日付別に予約する。アプリを開いたとき、日付・時刻・言語・進捗の変更時に補充・更新する。iOSの保留上限64件に対し、通常60件＋テスト1件に抑える。60日以上一度も起動しない場合は予約が尽きる制約を記録する。
- 過ぎた時刻への埋め合わせ通知は出さない。夏時間を含め各日の端末ローカル時刻で日時を作り、旅行やタイムゾーン変更は次の前面復帰で再照合する。開発用の日付送りは予約日時に適用しない。
- 自分の通知IDだけを更新・取り消す。同じ予約は再登録せず、同期を直列化してオン・オフや言語変更による重複・古い予約の復活を防ぐ。
- Expo SDK 58対応の `expo-notifications` を導入し、iOSはリモート通知と背景Pushを有効にしない。Androidは通常の通知チャンネルとbest-effort日時予約を使い、正確なアラーム用の追加許可を求めない。

### 配信

ネイティブ依存を追加するためversionを1.0.3へ上げ、appVersionのruntime分離を維持する。1.0.2のプレビューへOTAで追加せず、新しいiOS Previewビルドを既存アプリへ上書きインストールする。アプリの削除は不要。ビルドや実機配信は実施した事実だけを記録する。

## 受け入れ条件

- 初回オフ、明示操作での許可要求、許可拒否と設定復帰、オン・オフと時刻の保存復元を確認する。
- 当日の開封後に今日の通知だけが不要になること、全取得時の停止、未来60日の予約上限、過去時刻・夏時間・時刻／言語変更・重複防止・失敗後の再試行を自動検証する。
- 日本語・英語、ダークモード、小画面・文字拡大、Webの非対応案内、既存の言語設定と進捗の保持を確認する。
- lint・型チェック・Nodeテスト、iOS exportと設定生成を検証する。通知の受信・冷起動／前面でのタップ・OS設定変更・テスト通知は新ビルドのiPhoneで確認が必要で、自動テストを実機受信の確認済みとは扱わない。

## 実装・検証記録

- `expo install`でSDK 58対応の`expo-notifications ~58.1.8`を追加し、1.0.3へ更新した。通知設定を保存するProvider、日付ごとの予約照合、ネイティブAPIとのアダプターとWebの非対応表示を分離した。
- 設定にスイッチ・時刻変更・5秒後のテスト通知・許可拒否時の端末設定への導線を実装。時刻選択は既存`@expo/ui`の日時ピッカーを使用し、保存前にキャンセルできる。許可確認中・読込中・読込／保存／予約の失敗・全取得時の状態を表示する。
- 予約の更新を直列化し、処理開始時の最新の設定・言語・進捗を参照する。保存できなかったオン操作からは予約しない。オフの取り消しは、権限の再読み込みや進捗の読み込みが失敗していても先に実施する。履歴・権利・Map位置・言語の保存形式は変更しない。
- lint・型チェック、Nodeテスト11ファイル・計61ケースが成功。通知の初期オフ・設定検証・60日の上限・当日開封済み・過去時刻・全取得・夏時間・東京／ニューヨーク間の時差・時刻／言語変更・重複防止・部分失敗後の再試行を検証した。ネイティブアダプターはOS APIをモックして、iOSの通常／暫定許可、Androidのチャンネルとbest-effort予約、前面での表示抑止、タップの一度だけの処理と解除を確認した。
- Playwrightで実際のReact Providerとネイティブアダプターを動かし、OS API・保存APIをモデル化して、起動時の許可要求なし・オン時だけの許可要求・拒否・OS設定からの復帰・言語と時刻の変更／復元・当日の取り消し・テスト／オフ・読込／保存／予約の失敗と再試行・権限取り消しを確認した。端末OSを動かすテストではなく、受信を確認したものではない。
- Webで日本語／英語の非対応案内、通知許可を求めないこと、320×568・ダークモード・文字拡大での表示を確認。既存の言語設定・戻る導線・Mapカメラと進捗保持、および通常の10回ガチャ・保存失敗・二重タップ・再起動復元を回帰確認した。
- Expo設定のintrospectionとiOS exportが成功。生成されたiOSのentitlementsは空で、APNs権限と背景Pushモードを追加しないことを確認した。Androidに正確なアラーム用の許可は追加しない。
- クラウドのネイティブビルド・iPhoneへのインストール・実際の通知受信・ネイティブ時刻ピッカーの操作は未確認。[1.0.3の上書きインストール手順](eas-update.md)で確認する。60日以上起動しない場合に予約が尽きる点、タイムゾーン変更は前面復帰時に照合する点は、この実装の制約として残る。

### 再実行

```sh
npm run lint
npm run typecheck
node --test tests/*.test.cjs
MAP_TEST_URL=http://localhost:8081 node tests/browser/reminder-lifecycle.cjs
MAP_TEST_URL=http://localhost:8081 node tests/browser/reminders-web.cjs
npx expo config --type introspect
npx expo export --platform ios --output-dir /tmp/knowgacha-notifications-ios
```

ブラウザ確認にはPlaywrightとChromiumが必要。`MAP_PLAYWRIGHT_MODULE`で既存のランチャーを指定できる。ライフサイクルのモデルはローカルのテストページへ直接注入し、アプリのソースの差し替えや製品用のテストフラグを追加しない。
