# #6 知識グラフと件数別デモ

## 目的・範囲
知識を取得するにつれ分野がつながり、探索したくなるかを検証する。5・10件は出典を確認した独自の短文、100・500件は架空と明示した規模検証データを含む。同じデータを段階的に拡張する。

## 画面と操作（設計合意済み）
開発用メニュー → デモMap。常にデモ表示と、取得知識・周辺概念・関係の件数を表示する。5/10/100/500件の切り替え、5〜10件の一件ずつの追加、全体表示、一覧、ノード／関係の選択と周辺確認を提供する。デモ終了は実際のMapへ戻る。

未取得概念は名前・短い説明・取得済みとの関係まで。教材本文は取得後のみ。取得対象同士の線は両方取得した場合のみ、取得済みと周辺概念の線は片側の取得で表示し、未取得同士の線は表示しない。孤立点も残す。

## データ・永続化
ノード（知識／概念、短い説明、本文、出典、検証用の識別）、関係（種類・説明・根拠）、表示座標、取得ID集合を分離する。ノードは複数教材で共有可能。デモ状態は画面内のみで保持し、ProgressProviderの更新関数やAsyncStorageを使用しない。通常のガチャは既存3教材のまま。

## 内容と取得順
既存3教材 → 光ファイバー → CCD → 写真 → ダダ → コラージュ → ユーザーリサーチ → ユーザー中心設計。6件目の写真が共有概念「光」を通じ技術と芸術を結ぶ。関係は因果・同義を推測せず、資料が説明する範囲の利用・表現・調査手段に限定する。追加原稿は引用ではなく独自要約とする。

## 受け入れ条件
- 共有概念と根拠付きの関係、取得状態による公開範囲を自動テストする。
- 5/10/100/500件と5→10件の段階追加を実装する。
- 内容確認済みと架空データを表示上区別する。
- 全件表示・一覧選択・周辺確認が可能。
- デモ開始・切り替え・終了で実履歴を変更しない。
- lint・型チェック・データ検証を実施し、描画と端末検証の結果を区別して記録する。

## 関連・対象外

- Web実行確認：Linux上のChromium（Playwright 1.65.0）、390×844、タッチ有効、Expo開発モード。開発用入口→5→6→10件、関係の説明と出典、未取得概念で本文導線がないこと、周辺表示（光と隣接する3知識）、100／500件の全体表示、一覧の末尾500件目の選択、デモ終了→実Mapを確認。localStorageの履歴が開始前と完全一致し、ページ実行エラーなし。
- iOSバンドルのexport成功。これはiOSでの描画・操作確認の証拠ではない。
- 実機／ネイティブ描画は未検証。EAS Simulator利用可否の問い合わせは作業開始時のブランチにprojectIdがなく失敗した。物理端末の操作感とfpsは未計測。
- 観察：100／500件の全体表示では点とラベルが密集し、文字は読めない。位置の分布を見る用途とし、個別内容は一覧・選択・周辺表示で確認する。#7で表示密度と描画負荷を改善する。
