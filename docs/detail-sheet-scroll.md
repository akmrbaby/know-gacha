# 詳細シートの全文スクロール修正（2026-11-09）

## 修正前の設計・再現情報

ユーザーから、Mapの「詳細を開く」からシートを引き上げても一番下まで読めないとの報告。既存はiOSのSwiftUI BottomSheetにRNHostViewを埋め込み、その中の固定ヘッダーとReact Native ScrollViewで本文を表示している。Webの390×844ではhalf/fullともスクロール領域の高さが追従し、プログラムによる末尾への到達は可能だった。Webの結果をiPhoneでの再現・解消確認とは扱わない。

## 方針・範囲

iOSではシートと同じネイティブのScrollViewに本文のスクロールを任せる。固定ヘッダーと本文を別のRNHostViewへ分け、各ホストを内容の高さに合わせる。本文の全体の高さをネイティブスクロールへ伝え、見えている高さ・段階的展開・指操作をSwiftUI側で一貫して扱う。本文の末尾やセーフエリアを固定高で切らない。

AppSheetがスクロールを所有し、MapSheetと一覧は通常のViewで内容を渡す。Android/Webは従来と同じReact Native ScrollViewをAppSheet内で使う。スクロールの入れ子を作らず、選択対象が変わると先頭へ戻す。閉じるボタンとhalf/fullの展開は保持する。本文・翻訳・参考資料・保存データ・開封回数・Map位置は変更しない。ネイティブ依存・設定の追加もない。

## 受け入れ条件・確認計画

- 詳細の長い本文・末尾の参考資料・注意書きを、half/fullと小画面・文字拡大で最後まで読める。
- 一覧と関連語の選択、読書画面への移動、閉じた後のMap操作を維持する。対象変更時はスクロールが先頭になる。
- Webで実際の引き上げ・下方向へのスクロール操作と末尾の到達範囲を確認。lint・型チェック・既存のMap操作検証、iOSバンドル生成を行う。
- iPhone上での展開と指のスクロールは修正版で別途確認する。

参照: [SDK 58 BottomSheet](https://docs.expo.dev/versions/v58.0.0/sdk/ui/universal/bottomsheet/)、[ScrollView](https://docs.expo.dev/versions/v58.0.0/sdk/ui/universal/scrollview/)、[RNHostView](https://docs.expo.dev/versions/v58.0.0/sdk/ui/universal/rnhostview/)。

## 実装と検証

- iOSのAppSheetをネイティブColumn・固定ヘッダー・ネイティブScrollViewへ変更。各RNHostViewは縦方向に内容に合わせ、SwiftUIが本文全体の高さを扱う。MapSheetと一覧の内側のScrollViewは除き、AppSheetが一つのスクロールを所有する。選択IDをスクロールのキーにして対象変更時は先頭へ戻す。
- lint・型チェック・既存Nodeテスト7ファイル、iOS exportが成功。英語対応PR #32を土台に統合した後も、翻訳を含む8ファイル、日英切り替え・保存・読書・参考資料・MapのブラウザテストとiOS exportが成功。
- Chromiumの390×844でhalf状態の本文末尾に実際のスクロール操作で到達し、ハンドルをドラッグしてfullへ拡張した後も末尾まで読めることを確認。320×568・本文28px／行高40pxでも最後の注意書き全体が下余白付きで表示され、横はみ出しがないことを確認。
- 関係の選択→プレビュー→詳細を開き直すと先頭から表示されること、閉じた後の選択解除・拡大・一覧、進捗JSONの不変を確認。既存map-homeの初回／2回目開封・詳細／読書・タブ／サイズ変更／再起動時のMap位置復元・通常の開封演出も成功。
- Webでは元の現象を再現していないため、以上は回帰と表示範囲の確認。iPhoneでの元の不具合の解消確認は未実施で、修正版でユーザー確認を行う。
- 既存のExpo UIだけを使うJS修正のため、この修正単独ではバージョン変更・再ビルドは不要。英語対応の1.0.2導入に必要な新ビルドとは別の条件。
