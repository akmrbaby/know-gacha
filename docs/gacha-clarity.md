# Gachaの情報量と操作の整理

## 設計（2026-11-08、実装前）
ユーザーは「文字や項目が多く、全体が分かりにくい」と報告。未開封・演出中・開封済み・全件取得を一つの主領域で示し、同時に提示する選択肢を減らす。

- KnowGachaと「脳ガチャ — 好奇心の入口」は小さなブランド表示として保持。主見出しは「今日のガチャ」。日付と状態をまとめる。
- 未開封: カプセルと「今日の知識をひらく」、補足は「1日1回、無料でひらけます」ではなく料金に関する約束を追加せず「1日1回、新しい言葉に出会えます」の1行だけ。
- 開封中: 同じ主領域で演出とスキップを表示。開封済み: 実際の知識・短い紹介・主操作「解説を読む」。Mapへの遷移は1つの補助操作にする。「今日の知識へ戻る」など同じ状態への操作を除く。
- 翌日まで待つ説明は開封済み時だけ。全件取得時は次回開封を約束せず、最新の知識を読み返せる。
- 履歴は主領域の下。検証用デモと開発操作は「検証メニュー」へ折りたたみ、開封中は表示しない。通常productionでは検証メニューを表示しない。
- 保存・日次制限・抽選・Mapの挙動は変更しない。読み込み／失敗／再試行、二重押下防止を維持。文字拡大時は行を折り返しスクロールできる。

## 検証計画
Webで未開封→開封→解説／Map、今日の再訪、全件取得、履歴、デモ入口、ダーク、320px幅と文字拡大を確認する。lint・型チェックと既存ロジック検証を行う。実機のUI評価は更新後に別途確認する。

#14について、ユーザーはピンチ修正の実機確認に続き「性能測定はもうOkかな」と判断した。今回の実機評価として了承を得た記録であり、未取得の定量計測JSONやExpo Go／リリース比較を取得済みに変更するものではない。

## 実装・検証結果
未開封の主操作を1つにし、開封後は知識の紹介と読む操作を表示。Specimenの簡潔表示はGachaだけに適用し、読書画面の表示を保持する。履歴の総数は教材データから取得する。検証メニューは開封後も利用可能。開封直後は同じ位置の読むボタンへ連打が届かないよう350msだけ操作を待たせる。非同期保存完了の直後も同じ日付の開封を重複して開始しない。

lint・型チェック・7つのロジックテストファイルが成功。Chromium 390×844で開封の連打、1件のみ保存、読む、今日の再訪・再読み込み、Map、折りたたみデモ、全件取得時の最新知識再読を確認。320px幅・暗色・大きい文字でも横方向にページがはみ出さないことを確認。iPhoneの実際の操作感・VoiceOverは更新後の未確認項目。
