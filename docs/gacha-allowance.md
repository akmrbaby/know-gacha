# 通常ガチャの初期10回検証

## 設計（2026-11-09、実装前）
ユーザー指示: デモでなく通常ガチャを初期状態から10回引きたい。将来はダウンロード特典2回＋当日1回＝初期3回を想定。

今回の設定は初回特典9回＋当日1回＝10回。初回特典は繰り越し、当日分は日付ごとに1回で繰り越さず、当日分から先に消費する。初回特典数の定数を2にすると新規ユーザーは初期3回になる。保存済みユーザーの特典数は設定変更だけでは書き換えない。実運用の配布権利は将来サーバー等で管理する別段階。

保存は同じキーのversion 2へ移行し、初回特典総数・各開封の消費元を持つ。同日複数開封を許可するが教材の重複と当日分の重複消費を拒否。version 1の履歴・日付オフセットは保持し、旧履歴は当日分として移行、新しい初回特典9回を付与する。自動削除しない。保存成功後にだけ回数と履歴を反映し、失敗と連打で二重消費しない。

通常教材を3→10件へ拡張。既存デモの出典付き7件を共有データに移し、架空の規模検証データは通常プールに入れない。各教材の読書・出典・Map・履歴を対応。写真は取得可能教材へ昇格するので、未取得の教材と関係は他の未取得教材と同様に隠す。

GachaとMapに残り回数を表示。開封結果から「次をひらく」で次の1回へ進める。一括10連でなく、1回ずつ10件を確認する。教材が全件取得なら残高があっても開封せず、全件取得を明示する。preview/開発ビルドの検証メニューで確認ダイアログ付きの「初期10回からやり直す」を用意。履歴と回数だけを明示的に初期化、Mapカメラは保持する。既存端末も自動で履歴を失わず初期状態を試せる。

## 検証
初期10回、10件の重複なし、11回目を拒否、保存・再起動、翌日付与、特典2の初期3回、旧保存移行、破損／過剰消費の拒否、保存失敗・連打、Mapと読書・履歴、previewの明示的初期化を確認する。実機の10回確認は配信後。

## 実装と検証記録
- 初回特典数を`src/state/progress.ts`の`INITIAL_BONUS`で管理。保存済みv2は自分の付与数を保持する。
- 既存IDを保持して10件の通常教材、17ノード・18関係を定義。写真は通常取得の対象になり、取得後に知識間の関係を表示する。移管した7件の原稿は従来の短い出典付き試作原稿であり、公開用の校閲済み長文教材ではない。
- lint・型チェック・7テストファイルが成功。10回の保存往復と重複なし、11回目拒否、将来設定の初期3回、翌日付与、旧v1からの移行、同日当日分の重複・特典過剰消費・教材重複の拒否を検証。
- Web 390×844で通常画面を10回開封。連打、保存失敗後も残り10回、5回目の再読込後に残り5回、10回後の全件取得、読む・Map・履歴・再起動での記録維持を確認。Gachaの暗色・文字拡大・折りたたみデモも回帰確認。iOS Hermesバンドル生成成功。
- プレビューの検証メニューに初期化を追加。履歴を自動削除しない。実際のiPhoneの初期化確認ダイアログと10回開封の受信・動作は未確認。

## 保存形式の注意
旧JSはv2の複数回履歴を読めないため、旧v1のコードへ単純に戻す運用は不可。ロールバック時もv2読取りを維持する。権利と履歴は端末内の試作管理であり、再インストールをまたぐダウンロード特典の一意な配布は未実装。
